# Sendspin source-to-output latency

The `sendspin_source/status` endpoint reports a configured bridge target, the current amount of PCM buffered inside Music Assistant, and whether PCM has arrived recently. These are diagnostics, **not** a measurement of the time between sound entering a source and sound leaving a speaker. The frontend labels the bridge buffer accordingly.

In Sendspin source v1, an input chunk carries the server-clock time at which its first sample was captured. A player chunk carries the server-clock time at which its first sample should leave the audio port. Those timestamps describe the intended timeline. The pinned aiosendspin 9.1.1 `SourceBridge` uses input timestamps to absorb gaps and drift and exposes `occupancy_us`, but Music Assistant does not publish a per-sample capture-to-render mapping. The player protocol also does not return the actual acoustic output time. Summing the target buffer, observed occupancy, startup lead, and configured output delay would therefore create a plausible-looking number that is not a measured source-to-output latency.

To measure a specific route, send a short pulse or other identifiable signal to the source and record **both** the direct input reference and the destination speaker output on two channels of one recorder. The channels must share one clock. Measure the difference between corresponding pulse onsets or use cross-correlation over repeated pulses. Repeat after a cold start, after reconnect, and during steady playback; report median, spread, sample count, source client ID, destination player ID, output protocol, and the saved player delay. A phone recording only the speaker cannot establish the input time. Do not infer an AirPlay or Chromecast delay from another room's result.

Use the per-player output-delay control to align *speaker-to-speaker* arrival. The source-to-output measurement answers a different question: how late live input becomes audible everywhere. Sendspin's `output_delay_ms` is nonnegative and moves the port output earlier as it increases; AirPlay/Squeezelite `sync_adjust` has separate signed semantics. Re-measure after changing either value, switching protocol, changing physical output, or updating device firmware.

An automated acoustic value requires a capture device or player that reports a trustworthy render timestamp tied to the same clock. Until such hardware is identified, the API intentionally omits a `measured_latency_ms` field. A future adapter must distinguish scheduled/estimated transport latency from measured port and room-acoustic latency.
